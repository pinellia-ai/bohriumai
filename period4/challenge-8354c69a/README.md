# result-interpreter-anomaly — 实验结果解释与异常分析

> 波尔产品周赛第4期 · experiment 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「实验结果解释与异常分析」的可调用 Skill（result-interpreter-anomaly）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 解读实验结果并做排除式异常归因"
- 输入：`/input/case.json`（含 case_id、任务、数据字典/材料、output_contract）+ 数据文件。
- 输出：`/app/output/`（数据/图/代码 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  趋势 = 方向 + 幅度 + 与对照比较 + 条件限定："A 组随时间上升约 30%（相对基线），B 组持平"——引用具体数据点定位。
-  读数罗列不算趋势；组间/时间/剂量维度分别判。
-  判定规则：`{metric, 正常范围(基线±阈值/控制限), 判定方法}`——先定标准再找异常。
-  每个异常点：`{sample, batch, value, 与正常范围偏离程度(几倍σ/超限幅度), 确认是真异常还是正常波动}`。
-  候选原因清单（操作/设备/试剂/样本/环境）→ 逐个用数据排除或保留：`{假设, 支持证据, 排除证据, 状态: 排除 | 可能 | 待复核}`。
-  归因到具体样本/批次（有日志证据），不确定就标待复核——**不给没有排除过程的机理单猜**。

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；保留原始值/规则/结果/代码与质量检查。
- 缺失、异常、无法解释如实说明；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 数据/材料缺失 | status=failed 写明 |
| 无法解释的结果 | uncertainty 如实登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
