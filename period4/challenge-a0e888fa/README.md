# data-cleaning-pipeline — 科研数据清洗与处理

> 波尔产品周赛第4期 · analysis 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「科研数据清洗与处理」的可调用 Skill（data-cleaning-pipeline）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 清洗处理科研数据：规则编号、原始值保留、对账报告"
- 输入：`/input/case.json`（含 case_id、任务、数据字典/材料、output_contract）+ 数据文件。
- 输出：`/app/output/`（数据/图/代码 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  缺失形态清单（空串/空格/-999/NA 各多少）、重复记录（判定键）、单位混写点、值域越界点——体检报告先行。
-  规则：`{rule_id, 规则内容, 适用字段, 处理动作, 依据}`。如 R01：`-999 → NA`（依据：数据字典注明 -999 为缺失标记）。
-  单位换算：换算公式+精度留痕，原值保留列。
-  异常值：**不删除**——标记 `outlier_flag` 并给判定依据（越界/物理不可能），真实高值保留，交由分析阶段决定。
-  重复记录：判定键可解释（样品ID+批次），合并建议不直接删。
-  清洗前后对账：行数、缺失计数、单位分布——质量报告数字与清洗后表**一致**（第3期教训：报告和表对不上）。

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；保留原始值/规则/结果/代码与质量检查。
- 缺失、异常、无法解释如实说明；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 数据/材料缺失 | status=failed 写明 |
| 无法解释的结果 | uncertainty 如实登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
