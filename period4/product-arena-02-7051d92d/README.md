# academic-language-polisher — 写作02｜学术语言润色

> 波尔产品周赛第4期 · writing 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「写作02｜学术语言润色」的可调用 Skill（academic-language-polisher）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 润色学术语言：改对错误、统一术语、保持语义"
- 输入：`/input/case.json`（含 case_id、任务、事实底稿、output_contract）+ 材料文件。
- 输出：`/app/output/`（稿件文件 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  扫描原稿：`{限定词（may/only/under X conditions）, 术语出现处, 数字/单位, 因果与让步连接词}` 逐条登记——这些是"不许丢"的清单。
-  真修错误：语法/搭配/标点/用词——每处修改对应一个**具体错误类型**，不做无理由改写。
-  术语统一：全篇查术语表，漂移处（引言 vs 方法用词不同）统一为首选译名/写法。
-  语域调整：去口语化、去直译腔（中译英按英文惯用句式重组），但保持作者立场与语气强度。
-  润色稿 vs 基线逐项核对：限定词在否？数字单位改了吗？因果强度升了吗？指代对象变了吗？
-  任何丢失/升级 → 回改，不让"换一种说法"掩盖语义漂移。

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；事实/数字/引用保留来源或修改记录。
- 材料不足与冲突显式标注；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 底稿缺失/损坏 | status=failed 写明 |
| 约束冲突 | 以实际材料为准 + 登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
