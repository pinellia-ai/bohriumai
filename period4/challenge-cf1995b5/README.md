# experiment-design-builder — 实验方案生成与优化

> 波尔产品周赛第4期 · experiment 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「实验方案生成与优化」的可调用 Skill（experiment-design-builder）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 把研究目标落成可执行可评审的实验方案"
- 输入：`/input/case.json`（含 case_id、任务、数据字典/材料、output_contract）+ 数据文件。
- 输出：`/app/output/`（数据/图/代码 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  目标 → 可检验假设（H1/H0，可判定真假）；概念 → 操作性变量：`{变量, 操作定义, 测量方法, 精度}`。
-  对照设计：阴性/阳性/基线对照（每个假设至少一个可比对照）；判读标准：`{预期结果模式 → 结论映射}`（什么结果支持/推翻假设）。
-  每步骤：`{操作, 设备(型号), 试剂(规格/用量), 参数范围, 时间成本, 依赖步骤}`——可排期。
-  参数范围有依据（文献/SOP/仪器量程），依据标注。
-  预设失败模式：`{失败情形, 触发信号, 处置动作, 对结论的影响}`——实验做砸时知道下一步。
-  方案依据（文献/SOP）、假设（未经证实的前提）、**需专家确认项**（安全/关键参数）显式标注。

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；保留原始值/规则/结果/代码与质量检查。
- 缺失、异常、无法解释如实说明；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 数据/材料缺失 | status=failed 写明 |
| 无法解释的结果 | uncertainty 如实登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
