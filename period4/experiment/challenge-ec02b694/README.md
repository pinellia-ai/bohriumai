# parameter-optimizer — 实验参数优化建议

> 波尔产品周赛第4期 · experiment 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「实验参数优化建议」的可调用 Skill（parameter-optimizer）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 给出联合可行的实验参数优化开机方案"
- 输入：`/input/case.json`（含 case_id、任务、数据字典/材料、output_contract）+ 数据文件。
- 输出：`/app/output/`（数据/图/代码 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  对目标指标影响大 + 存在牵制 → 关键参数；依据（文献/预实验/机理）标注。
-  牵制关系显式：`{参数A↑ → 指标↑ 但 参数B代价↑}`——联合可行域概念建立。
-  每个关键参数：`{建议值, 浮动区间, 响应指标, 测量方法, 依据(文献[2]/SOP/预实验)}`。
-  **联合可行**：建议值组合逐条过约束边界（量程/耐温/安全阈值），越界组合不出。
-  按预算选：单变量扫描（预算小）→ 正交设计（多参数）→ 响应面（需精细曲面）；给出试验点数、机时/成本估算、判优标准（响应指标+阈值）。
-  每个建议的代价明说：转化率 vs 副产物/能耗、采样密度 vs 成本——决策留给用户但利弊算清。

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；保留原始值/规则/结果/代码与质量检查。
- 缺失、异常、无法解释如实说明；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 数据/材料缺失 | status=failed 写明 |
| 无法解释的结果 | uncertainty 如实登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
