# protocol-compare-selector — 实验方案比较与选择

> 波尔产品周赛第4期 · experiment 赛道 · Skill 交付包使用与方法说明

## 1. 这是什么

围绕「实验方案比较与选择」的可调用 Skill（protocol-compare-selector）：组织方为本题准备 3 个固定案例。每个案例包含任务说明、科研材料、必要的输入约束和评分所需的证据范围；案例会以相同内容分别交给基础 Agent 和加载参赛 Skill 的 Agent。你不需要自带正式测试案例，也不需要提交预先写好的答案。…

评测方式：安装后由官方 DeepSeek Harness 在 3 个固定案例运行（64 请求/900秒/16384token），与基础 Agent 对照评分。本包不含预制答案。

## 2. 快速调用

- 触发："请按本 Skill 比较实验路线并给出可辩护选择"
- 输入：`/input/case.json`（含 case_id、任务、数据字典/材料、output_contract）+ 数据文件。
- 输出：`/app/output/`（数据/图/代码 + result.json，字段以 output_contract 为最高优先）。

## 3. 方法概述

-  五维：设备机时 / 耗材成本 / 参数窗口（可行范围宽窄）/ 风险等级 / 证据强度（预期结论的可信度）。
-  每路线每维：`{score, 依据(材料内证据/文献/估算)}`——依据引用具体文档。
-  加权总分 + 维度短板提示（某路线某维极差即使总分高也要警示）。
-  敏感性：换权重（如成本敏感 vs 证据敏感）排序是否翻转——翻转时明示两种结论。
-  选择：`{选定路线, 决定性优势}`；**每条被弃路线给具体舍弃理由**（输在哪个维度、差多少），不敷衍（"综合考虑不选"不合格）。
-  可辩护性自检：他人按同一标准能否复现同一选择？

## 4. 契约速览

- case_id 原样；status ∈ success|partial|failed；保留原始值/规则/结果/代码与质量检查。
- 缺失、异常、无法解释如实说明；partial 时已完成部分完整可交；不编造。

## 5. 异常速查

| 情况 | 处置 |
|---|---|
| 数据/材料缺失 | status=failed 写明 |
| 无法解释的结果 | uncertainty 如实登记 |
| 预算不足 | 落盘 partial，gaps 列剩余 |
| contract 与本文件冲突 | 以 case.json output_contract 为准 |
