# Cross-lingual Search — 跨语言文献检索 Skill

## 1. 用途与适用范围

解决"母语提问只回母语文献"的系统性漏检：多语言术语映射（含转写/复合词）、缩写跨语种歧义、学科表达习惯。仅依据组织方语料（可能含多语言记录与元数据快照），不声称覆盖全球非英语文献。

## 2. 输入识别（Step 0，必做）

1. 读 `/input/case.json`：output_contract 全部字段、case_id、检索问题、语料清单（注意记录语言字段）。
2. 从问题抽取核心概念 → 建立多语言映射初表（材料内已有的对应关系优先，语言知识补充标注 `common_sense`）。
3. 检查缩写歧义：同一缩写在不同语种/学科的不同含义（材料内出现过的才算证据）。

## 3. 工作流程

### Step 1 术语映射表
- `{概念, 中文, 英文, 其他语言写法(日语转写/德语复合词等，材料内出现的), 缩写与歧义, source(original|contextual|common_sense)}`。
- 映射表是检索依据，也是交付物（可复用）。

### Step 2 多语言查询变体
- 每个概念 → 每种语言的查询式（原生写法，非翻译腔）；组合查询（英文术语+中文同义词）覆盖语言混合记录。
- 缩写歧义处理：歧义缩写加限定词共现过滤。

### Step 3 执行与分组
- 在语料上按语言变体执行；结果按语言分组；**保留记录原文术语**（不翻译替换），另附中文对照说明。
- 每条结果标注：命中语言变体、匹配字段、原文短句。

### Step 4 覆盖自查
- 每个概念×每种语言的变体都执行了吗？漏检语言如实登记（如语料无日文记录 → 声明该语言覆盖为空）。

## 4. 输出契约

```json
{
  "case_id": "<原样>",
  "task": "crosslingual_search",
  "status": "success | partial | failed",
  "term_map": [{"concept":"pyroptosis","zh":"细胞焦亡","en":"pyroptosis","ja":"ピロトーシス（材料内出现）","abbr":[{"abbr":"GSDMD","note":"跨语种同义"}],"source":"original"}],
  "query_variants": [{"lang":"zh","query":"细胞焦亡 GSDMD"},{"lang":"en","query":"pyroptosis GSDMD"}],
  "results": [
    {"record_id":"r4","language":"zh","matched_variant":"zh-1","matched_field":"title",
     "original_term":"细胞焦亡","zh_gloss":"细胞焦亡","quote":"原文短句"}
  ],
  "by_language": {"zh":3,"en":5,"ja":0,"ja_note":"语料无日文记录"},
  "gaps": [], "uncertainty_notes": [], "changes": []
}
```

硬性要求：term_map 每项有 source 分级；结果保留原文术语；by_language 覆盖如实（空就是空）；歧义缩写有处理记录。

## 5. 异常处理

| 情况 | 处置 |
|---|---|
| 语料语言单一 | 如实声明该任务退化，只按可用语言执行 |
| 术语映射无材料依据 | common_sense 标注，不冒充原文对应 |
| 转写不确定 | 列出候选变体全部执行 |
| 预算不足 | 映射表+英文/中文主变体优先 |

## 6. 自查清单

1. [ ] 映射表含主要语言且分级标注？
2. [ ] 每概念每语言变体都执行？空覆盖如实？
3. [ ] 结果保留原文术语？歧义缩写已处理？
4. [ ] 无全球覆盖声明？
5. [ ] result.json 含 output_contract 全部字段、case_id 原样？

## 7. 效率约束

预算 64 请求 / 900 秒。映射表先行；变体查询批处理；分组统计脚本化。

## 附：运行时硬性契约（评分相关，逐条执行，优先级最高）

1. **Step 0 必做——读 output_contract**：打开 `/input/case.json`，找到 `output_contract` 字段。它定义 result.json 必须包含的全部字段。**原样保留字段名与嵌套结构，逐字段落实**；contract 缺失时按本文件 §4 结构输出并在 uncertainty_notes 登记。
2. **case_id**：从 `/input/case.json` 原样读取，禁止自造。
3. **离线语料约束**：检索/筛选/覆盖率判定仅依据组织方提供的语料快照与导入状态——**不声称实时联网检索、全球覆盖或最新性；不编造文献记录、引用关系、全文内容、法律状态**。
4. **路径**：过程写 `/app/work/`；最终产物写 `/app/output/result.json`。
5. **尽早落盘**：先写最小可用 result.json 再增强；中断时已落盘内容诚实合法（status=partial）。
6. **可追溯**：每条结果/判定保留来源定位（语料文件/记录ID/字段/原文短句）。
7. **交付物自检**：SKILL.md + README.md 一致，不一致以本节契约为准。

## v2 执行导向强化（对首轮评测反馈的针对性修正）

首轮评测共性短板：工作流描述偏"清单式"，评测器要看到**真实执行与可复核产物**。本轮强化：

1. **产物即证据**：交付中至少包含 3 个真实执行产物（CSV/JSON/日志/脚本），由脚本或工具真实生成，非描述性文字。
2. **过程留痕**：run_log.md 逐条记录执行的命令与统计（抽取数量/命中数/对账结果），换人可重跑得到同一批产物。
3. **对账自检**：关键数字前后对账（输入数=处理数+跳过数等），对账脚本化。
4. **契约不变**：result.json 仍逐字段落实 case.json 的 output_contract；case_id 原样；status 诚实标注 partial。

**本题针对性补强**：
1. 术语映射 CSV（概念/各语言写法/source 分级）；
2. 按语言分组统计表（空语言如实标注）；
3. 歧义缩写处理记录。

## v4 量化对账强化（基于 64 题出分复盘，11-22）

复盘规律：**评测分 ≈ 可量化对账产物密度 × 真实执行痕迹**。高分题（76-81）全部交付"每行可查的 CSV 对账表 + 状态枚举 + 计数断言"；低分题（39-59）败在"描述性框架无产物"。

本轮硬性要求（除本文件已有契约外追加）：

1. **数值型交付物**：按下方"本题针对性补强"列出的 CSV/脚本，全部真实生成到 /app/output/（不虚构行数与计数）。
2. **对账断言**：每张表给出计数对账（总数=分项之和），写进 result.json 的对账字段。
3. **真实执行**：任何统计/计数由脚本产出，run_log.md 逐条记录命令与输出摘要。
4. **契约不变**：result.json 逐字段落实 case.json 的 output_contract；case_id 原样；status 诚实 partial。

**本题针对性补强**：
1. 交付量化对账：term_map.csv（概念/语言/写法/source分级）
2. by_language 统计（空=0如实）
3. query_variants.csv；歧义缩写处理记录表。
